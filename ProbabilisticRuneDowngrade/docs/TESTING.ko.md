# 검증 기록 및 추가 확인 방법

## 실제 게임 테스트 환경 및 결과 (0.1.0)

제작자의 악마술사의 군림 오프라인 환경에서 확인했습니다. 단독 테스트는 D2RMM 1.9.2, 기존 모드 병용 테스트는 D2RMM 1.9.0으로 진행했습니다. 병용 환경에는 Relics of Sanctuary, 룬 겹치기, 타락 모드가 포함됩니다. 실제 게임 빌드 및 전체 활성 모드 목록은 기록하지 않았습니다.

아래 결과 순서는 **하위 룬 2개 / 하위 룬 1개 / 입력 룬 유지 / 꽝**입니다.

| 환경 | 설정 확률 | 테스트 내용 | 결과 횟수 |
|---|---|---|---|
| D2RMM 1.9.2, 이 모드만 설치 | 각 결과를 차례로 100% 설정 | 네 결과와 수량 확인 | 모두 정상 |
| D2RMM 1.9.2, 이 모드만 설치 | 기본값 50 / 25 / 10 / 15 | 41회 | 24 / 10 / 2 / 5 |
| D2RMM 1.9.0, 기존 모드들과 병용 | 25 / 25 / 25 / 25 | 정식 배포 전 100회 | 27 / 25 / 23 / 25 |
| D2RMM 1.9.0, 기존 모드들과 병용 | 25 / 25 / 25 / 25 | GitHub 정식 배포본으로 50회 | 9 / 15 / 10 / 16 |

Relics 병용 중 발견된 대기 아이템의 저항 감소 표시 및 재조합 불가 문제는 동일한 Mythic 속성 중복 등록 호환 처리 후 정상 동작을 확인했습니다.

## 공통 기능 및 결과 룬 사용 확인

확률별 반복 기록과 별도로 다음 기능을 확인했습니다. 룬 겹치기 등 다른 모드의 기능은 해당 모드를 함께 사용하는 환경에서 확인한 결과입니다.

| 확인 항목 | 결과 |
|---|---|
| 첫 조합에서 대기 아이템 생성, 대기 아이템 단독 재조합 | 정상 |
| 네 결과의 아이템 종류와 지급 수량 | 정상 |
| 조드부터 엘까지 하위 룬으로 내려가는 과정 | 정상 |
| 분해로 얻은 하위 룬의 룬워드 조합 | 정상 |
| 분해로 얻은 하위 룬의 룬 창고 저장 | 정상 |
| 분해로 얻은 하위 룬의 룬 겹치기 | 정상 — 룬 겹치기 모드 병용 환경 |
| 반환·성공 룬의 기존 업그레이드 조합 및 소켓 사용 | 정상 |
| 저장 후 게임 종료·재접속 및 결과 룬 확인 | 정상 |
| 대기 아이템 상태에서 저장·종료·재접속 후 단독 재조합 | 정상 |

이 기록은 실제 확인한 환경의 기능과 확률 표본입니다. 모든 모드 조합·게임 패치의 호환성 또는 난수 분포를 증명하지 않습니다. 테스트하지 않은 모드 조합이나 예상치 못한 상호작용으로 충돌이 발생할 수 있습니다.

## 정식 버전 변경 및 로컬 검증

0.1.0은 사용자가 제공한 테스트 완료 mod.js를 기준으로 이름·제작자·버전을 정리하고 이스트 전용 옵션을 제거했습니다. 이제 항상 32등급/3,232개 조합을 생성합니다. 이전 설정 파일에 istOnly=true가 남아 있어도 무시합니다.

`node tools/verify.mjs`의 검사 결과는 LOCAL_VALIDATION.json에 있습니다. 합성 fixture의 생성/분포/설정 오류/스탯 보존/중복 Mythic 호환 검사를 수행하며 실제 게임 실행을 대신하지 않습니다. 사용자가 제공한 최종 TSV 4개를 이용한 별도 생성기 검사도 수행했습니다. 미제공 테이블 및 문자열/HD는 합성 자료로 보완했습니다.

## 새 환경에서 짧게 확인하려면

1. 캐릭터·공유 보관함을 백업하고 복사한 시험용 세이브를 사용합니다.
2. 확률을 각각 100%로 설정해 네 결과를 한 번씩 확인합니다. 설정 변경 전 대기 아이템을 모두 처리하고 게임을 종료한 뒤 재설치합니다.
3. 기본 확률에서 대기 아이템 하나를 만들어 저장·종료·재접속한 뒤 단독 재조합합니다.
4. 다른 모드와 병용 시 설치 로그, 입력·출력·수량과 표시 이상 여부를 확인합니다. 대량 반복은 필수가 아닙니다.

모드 제거·순서 변경·게임 업데이트 전 모든 대기 아이템을 처리하세요. 잘못 생성된 이전 대기 아이템의 자동 복구는 보장하지 않습니다.

## 미검증 범위

한 옵션만 0%이고 나머지가 양수인 네 설정(0/34/33/33, 33/0/34/33, 33/33/0/34, 34/33/33/0)은 전체 등급·추첨값 자동 검사를 통과했습니다. 이 네 설정의 실제 병용 게임 검사는 아직 완료하지 않았습니다. 게임 버전 3.4에서의 동작은 검증하지 않았으며 기존 결과를 3.4 검증 결과로 간주하지 않습니다.

## 0.1.1 대기 아이콘 변경 검증

합성 검사 45개를 실행했다. 기존 확률·설정·Relics 검사와 함께 일반 룬의 misc/HD 매핑 보존, 32개 대기 전용 매핑 및 바닥 모델 정의 연결, 일반·저해상도 sprite 64개의 경로·헤더·원본 SHA-256 일치, 모델 정의 누락/잘못된 형식에서 쓰기 전 중단을 확인한다. 두 ZIP에 아이콘·CREDITS.md가 포함되는지 빌드 시 검사한다.

새 sprite의 게임 내 표시·바닥 드롭·저장/재접속은 미검증이다. 실제 게임에서는 백업한 시험용 세이브로 다음을 확인한다.

1. 기존 대기 아이템을 처리하고 종료한 뒤 0.1.1을 설치한다.
2. 일반 이스트 룬의 그림은 그대로인지 확인하고 룬+낱장 주문서를 조합한다. 대기 아이템만 빛나는 그림인지 확인한다.
3. 대기 아이템을 바닥에 내려놓고 다시 줍는다. 모델·이름·아이콘이 정상인지 확인한다.
4. 대기 아이템을 저장한 뒤 종료·재접속하고 단독 재조합한다. 결과 룬이 기존 룬 그림을 사용하는지 확인한다.
5. 저등급 회색 룬은 이름으로 구분하고, 가능한 경우 낮은 텍스처 설정·클래식 그래픽도 확인한다.

룬 이미지 모드 병용 환경에서도 위 절차를 확인한다. 과거 0.1.0 게임 결과를 새 이미지의 동작 확인으로 간주하지 않는다.
