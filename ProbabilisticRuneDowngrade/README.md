# Probabilistic Rune Downgrade — 0.1.0

제작자: **빵길빵길**. 악마술사의 군림(Reign of the Warlock) 전용 오프라인 D2RMM 모드입니다.

룬 1개 + 낱장 감별 주문서 1개 → 분해 대기 아이템 → 추가 재료 없이 대기 아이템만 다시 조합하여 결과를 받습니다.

| 결과 | 기본 확률 |
|---|---:|
| 바로 아래 룬 2개 | 50% |
| 바로 아래 룬 1개 | 25% |
| 입력 룬 1개 반환 | 10% |
| 감별 주문서 1개 — 꽝 | 15% |

엘드(r02)부터 조드(r33)까지 전체 32등급의 룬을 분해할 수 있습니다. 엘(r01)은 분해하지 않습니다. 네 결과의 확률을 각각 0에서 100 사이의 정수로 설정할 수 있으며, 합계가 정확히 100이어야 합니다. 첫 조합에서 입력 룬과 주문서를 소비하며 성공/유지에는 주문서를 돌려주지 않습니다.

## 왜 두 번 조합하나요?

일반적인 큐브 조합법만으로는 한 번의 조합에서 네 가지 아이템 결과 중 하나를 설정한 확률대로 골라 지급하기 어렵습니다. 이 모드는 타락 모드에서 볼 수 있는 ‘먼저 대기 아이템을 만들고, 다시 조합해 결과를 받는 방식’에서 착안했습니다. 특정 타락 모드의 내부 구현과 같다는 뜻은 아닙니다.

첫 번째 조합에서 게임이 1부터 100 사이의 추첨값을 대기 아이템에 저장하고, 두 번째 조합에서 그 값에 맞는 결과를 지급합니다. 두 번째에 다시 추첨하는 것은 아니며, 추가 재료도 필요하지 않습니다.

## 설치

소스 저장소에서는 `ProbabilisticRuneDowngrade` 폴더를 D2RMM의 `mods` 폴더에 복사할 수 있습니다. 일반 사용자는 아래 설치 ZIP을 받는 방법을 권장합니다.

간편 설치용은 `ProbabilisticRuneDowngrade-0.1.0-mods-only.zip`입니다. `mods` 폴더와 모드 파일·라이선스만 포함하며, D2RMM 실행파일이 있는 폴더에 압축을 풀면 `mods/ProbabilisticRuneDowngrade/`로 배치됩니다. 별도 개발 문서를 복사할 필요는 없습니다. 압축 해제 도구가 ZIP 이름의 바깥 폴더를 자동 생성하지 않는지 확인하세요. 기존 문서 포함 ZIP도 계속 제공합니다.

1. 게임을 종료하고 오프라인 캐릭터와 공유 보관함을 백업합니다.
2. 간편 설치 ZIP 또는 문서 포함 ZIP 중 하나를 D2RMM 루트 폴더에 풉니다. `mods/ProbabilisticRuneDowngrade/mod.json`이 있어야 합니다.
3. D2RMM 1.9 이상에서 **Probabilistic Rune Downgrade**를 선택하고 확률을 설정합니다.
4. Relics of Sanctuary와 함께 사용한다면 우리 모드를 그 뒤에 두고 Install Mods를 실행합니다.
5. D2RMM 설정에 맞게 오프라인 게임을 실행합니다. 기존 게임 캐릭터 버전 호환성을 확대해 주장하지 않으며 악마술사의 군림용 데이터 `global/excel`만 생성합니다.

## 검증 범위

제작자의 실제 플레이 환경에서 다음과 같이 테스트했습니다. 결과 순서는 **하위 룬 2개 / 하위 룬 1개 / 입력 룬 유지 / 꽝**입니다.

| 환경 | 설정 확률 | 테스트 내용 | 결과 횟수 |
|---|---|---|---|
| D2RMM 1.9.2, 이 모드만 설치 | 각 결과를 차례로 100% 설정 | 네 결과와 수량 확인 | 모두 정상 |
| D2RMM 1.9.2, 이 모드만 설치 | 기본값 50 / 25 / 10 / 15 | 41회 | 24 / 10 / 2 / 5 |
| D2RMM 1.9.0, 기존 모드들과 병용 | 25 / 25 / 25 / 25 | 정식 배포 전 100회 | 27 / 25 / 23 / 25 |
| D2RMM 1.9.0, 기존 모드들과 병용 | 25 / 25 / 25 / 25 | GitHub 정식 배포본으로 50회 | 9 / 15 / 10 / 16 |

병용 환경에는 Relics of Sanctuary, 룬 겹치기, 타락 모드가 포함되어 있습니다. Relics 호환 처리 후 조합과 결과 지급이 정상 동작했습니다.

확률별 반복 테스트와 별도로 다음 공통 기능도 확인했습니다.

- 조드부터 엘까지 하위 룬으로 분해하는 과정과 네 결과의 지급 수량
- 분해로 얻은 하위 룬의 **룬워드 조합, 룬 창고 저장, 룬 겹치기**
- 반환·성공 룬의 기존 업그레이드 조합 및 소켓 사용
- **저장 후 게임 종료·재접속** 및 결과 룬 확인
- 대기 아이템 상태에서 저장·종료·재접속 후 단독 재조합

룬 겹치기 등 다른 모드의 기능은 해당 모드를 함께 사용하는 환경에서 확인했습니다.

위 기록은 테스트한 환경의 결과이며 모든 게임 패치와 모드 조합의 호환성을 보장하지는 않습니다. 반복 횟수만으로 설정 확률의 정확성이 완전히 증명되는 것은 아닙니다. 로컬 생성기 검사와 실제 게임 검증은 구분합니다. [검증 기록](docs/TESTING.ko.md), [로컬 검사](docs/LOCAL_VALIDATION.json), [구현 기록](docs/IMPLEMENTATION.md)을 참고하세요.

## Relics of Sanctuary 호환 및 저장 주의

Relics가 완전히 같은 `item-mythic` 속성을 두 번 등록하면 두 번째 이후 속성의 내부 코드에 별칭을 부여합니다. 첫 Mythic 정의와 모든 행 위치·스탯은 유지하고 Relics 소스는 수정하지 않습니다. 내용이 서로 다르면 설치를 중단합니다. 기타 중복 코드의 자동 복구는 제공하지 않습니다.

**모드 제거·순서 변경·다른 스탯 추가 모드 설치·게임 업데이트 전 대기 아이템을 모두 처리하고 저장을 백업하세요.** 추첨값은 첫 조합에서 고정됩니다. 대기 아이템을 남겨 둔 채 확률만 바꾸면 저장된 값에 새 확률이 적용되어 결과가 재해석됩니다. 스탯 ID는 현재 테이블 끝에 추가되므로 모드 구성이나 순서 변경으로 저장 호환성이 달라질 수 있습니다. 이전에 잘못 생성된 대기 아이템의 자동 복구는 보장하지 않습니다.

테스트하지 않은 모드 조합이나 예상치 못한 상호작용으로 충돌이 발생할 수 있습니다.

## 개발 및 배포물 제작

저장소 루트에서 Node.js 18+로 `node tools/verify.mjs`, Python 3에서 `python3 tools/build.py`를 실행합니다. 합성 fixture로 설치 생성기를 검사하고 ZIP 내부 파일별 SHA-256 및 ZIP 자체의 SHA-256 파일을 생성합니다. 공개 조사 테이블이 준비된 경우에만 해당 원문을 사용하는 별도 검사를 실행합니다. 게임 원본 테이블·이미지 및 타 모드 소스를 배포하지 않습니다.

GitHub Actions는 mod.json 버전과 일치하는 v 접두사 태그에서 검증 및 ZIP 빌드를 수행합니다. 로컬 빌드만으로 원격 공개 릴리스가 생성되는 것은 아닙니다.

MIT 라이선스는 이 저장소에서 작성한 코드와 문서에 적용합니다. Diablo II 및 게임 자산의 권리는 각 권리자에게 있습니다.
